## TASK

For each document:

1. **Relevance gate.** Decide whether the document contains a personal account of the author's own mutual fund or SIP experience in India. If not, set `"relevant": false` and `"signals": []`.
   - Relevant: the author describes their own SIP starting, paying, missing, pausing, stopping, restarting, increasing, reducing, or reviewing; their own mandate/debit/statement problem; their own expectation, emotion, or decision about a SIP; or a personal question about their own SIP or goal.
   - Not relevant: generic app praise or complaints that only mention SIP/mutual funds in passing.
   - Not relevant: fund recommendations, app comparisons, third-party advice, news, explainers, promotions, or "you should invest" posts.
   - Not relevant: stock, IPO, F&O, crypto, or US-stock trading experiences.
   - Not relevant: generic KYC, app-bug, or feature-request posts with no personal SIP/mutual-fund experience.
2. **Personal, not generic.** Code only the author's own experience. Do not code advice the author gives to others. Do not code a generic statement about what investors should do. Do not code a friend's, family member's, or client's experience: "I helped a friend..." is not the author's own SIP experience.
3. **Evidence before code.** Every non-unknown code must be directly supported by the quote. If the quote does not explicitly show the code, use `unknown` or `[]`. Do not infer a code from the app category, a negative rating, or the general topic.
   - Do not code `started_sip` just because the app is "for SIPs" or the author says "I use the app". Code it only if the author says they started a SIP.
   - For `started_sip`, `increased_sip`, `decreased_sip`, `paused_sip`, `stopped_sip`, or `restarted_sip`, the quoted sentence must contain the word "SIP". A quote about a mutual-fund portfolio change without "SIP" is not enough.
   - Do not code `continues`, `paused`, `stopped`, `returned`, `reduced`, or `increased` unless the author explicitly says so.
   - "I tried to start" is not `started_sip`. "I requested to cancel" or "I am trying to stop" is not `stopped_sip` or `stopped`. Code the attempt only when the author confirms the action actually happened; otherwise use the appropriate help-seeking/behaviour code and `outcome=unknown`.
   - Do not code `journey_stage` from app features. Use tenure language ("3 months", "1 year") or a stage-specific event (first statement, mandate failure).
   - Do not code emotions from a negative rating alone. Use explicit emotional language ("I was scared", "I felt stupid", "very frustrating").
   - Do not code segment cues unless the author states them or they are unmistakable. If you code any segment cue, include a separate exact `segment_quote` that contains that evidence; otherwise set `segment_quote` to null.
4. **Quote.** Every signal must include an exact quote copied from the document text. Do not paraphrase. Do not fix spelling. Do not translate the quote. The quote must be a single contiguous span, not several sentences joined with "...". Keep it under 400 characters. The quote must contain the evidence for all behavioural, trigger, emotion, expectation, help-seeking, outcome, and journey-stage codes. If you cannot quote it exactly, do not create the signal. Segment cues may be supported by the separate `segment_quote`.
5. **Signals.** Extract 1 to 3 signals per relevant document. A signal is a distinct claim. Split separate claims into separate signals. Do not create a signal for every sentence. A relevant document may have zero signals if it contains no codeable evidence; in that case, set `"relevant": true` and `"signals": []`.
6. **Unknowns.** Use `"unknown"` for a scalar field with no evidence. For multi-label fields, return `[]` when there is no evidence; do not return `["unknown"]`.
7. **Codebook only.** Multi-label arrays are allowed. Use only codes from the codebook.
8. **Confidence.** `high` = explicit language for the key fields and an unambiguous quote; `medium` = one element inferred from strong context; `low` = sarcasm, mixed language, or ambiguity that needs human review.
9. **Language.** Keep Hinglish and regional-language wording in the quote. `notes` may contain a short English gloss, but never replace the quote with the gloss.
10. **Privacy.** Do not include usernames, phone numbers, account numbers, emails, or URLs in the quote.
